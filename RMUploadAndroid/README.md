# RMUpload (Android)

Android port of the iOS app in `../RMUpload`: uploads PDF and EPUB files to your reMarkable cloud
account using the same API as the "Read on reMarkable" Chrome extension.

## Build & install

Gradle 8.9 does not run on JDK 25, so point it at JDK 21:

```sh
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
./gradlew installDebug      # build and install on the connected device
./gradlew assembleRelease   # app/build/outputs/apk/release (signed with the debug key)
```

## Usage

- Log in with your reMarkable account.
- Tap **+ → Files…** to pick PDFs/EPUBs, or from any app use **Share → RMUpload** / **Open with → RMUpload**.
- Tap **+ → Webpage…** and enter a URL, or share a link from the browser to RMUpload: the page is
  rendered off-screen into a paginated PDF (3:4 pages, the reMarkable's shape) and queued.
- Optionally convert EPUBs into notebooks, then tap **Send to reMarkable**.
  Files land in the root folder of your reMarkable.

## How it works

Same protocol as the iOS app (see `../RMUpload/README.md`), with two platform differences:

- Login runs in an in-app WebView, which intercepts the redirect to the extension's
  `chrome-extension://…/callback.html`. Custom Tabs can't hand that scheme back to an app.
  Google/Apple social login may refuse to run inside a WebView; email + password works.
- Webpages are printed with WebView's print adapter, driven directly by `android.print.PdfPrinter`
  (it lives in that package because the print callbacks have package-private constructors).
- Tokens are stored in SharedPreferences, encrypted with an AES key kept in the Android Keystore.

- Reader mode (on by default) runs `assets/reader.js` (the extension's Readability + DOMPurify,
  generated by `../tools/build_reader.py`) in the page and prints just the article text and images.

This uses reMarkable's private API and the extension's OAuth client; it may break whenever they change it.
